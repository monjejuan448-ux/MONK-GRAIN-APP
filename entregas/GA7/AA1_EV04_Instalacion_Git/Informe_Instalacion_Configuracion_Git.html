1. Introducción

Este documento registra, paso a paso, la instalación y configuración del control de versiones empleado en el proyecto MONK GRAIN: Git en el equipo local y su vinculación con GitHub como repositorio remoto.

Los comandos y las salidas que aparecen son los del equipo real donde se desarrolla el proyecto, no ejemplos de manual. El entorno es Linux Mint 22.3, de modo que la instalación usa apt; al final se indican los equivalentes para Windows y macOS.

2. Objetivo

Instalar y configurar la herramienta de control de versiones en sus dos ámbitos —local y web— dejando constancia de cada paso, de modo que el procedimiento pueda repetirse en otro equipo y el entorno quede verificado antes de empezar a versionar el proyecto.

4. Paso 1 — Instalación de Git

Se actualiza el índice de paquetes y se instala Git:

$ sudo apt update
$ sudo apt install git

Se comprueba que quedó instalado consultando su versión:

$ git --version
git version 2.43.0
Captura 1 — Instalación de Git Terminal mostrando sudo apt install git y la salida de git --version

5. Paso 2 — Configuración de la identidad

Git firma cada versión con un nombre y un correo. Sin ellos se niega a registrar la primera versión, y con ellos mal puestos el historial atribuye el trabajo a quien no es. Se configuran de forma global, para todos los repositorios del equipo: 

$ git config --global user.name "Eliana Chacon"
$ git config --global user.email "juanmo1082@hotmail.com"

Se configura además que la rama inicial se llame main. Es el nombre que usan hoy GitHub y GitLab por defecto, y evita la incoherencia de tener repositorios con master y otros con main: 

$ git config --global init.defaultBranch main

Se verifica la configuración:

$ git config --global --list
user.name=Eliana Chacon
user.email=juanmo1082@hotmail.com
init.defaultbranch=main
Captura 2 — Identidad configurada Terminal mostrando los tres comandos git config y la salida de git config --global --list

6. Paso 3 — Creación del repositorio local

Dentro de la carpeta del proyecto se inicializa el repositorio:

$ cd ~/Desktop/ANALISIS\ Y\ DESARROLLO\ DE\ SOFTWARE/MONK-GRAIN-APP
$ git init
Initialized empty Git repository in .../MONK-GRAIN-APP/.git/

Antes de registrar nada se define qué no debe versionarse, en el archivo .gitignore. Es un paso que conviene hacer primero: una vez que un archivo entra en el historial, sacarlo exige reescribirlo. 

# Entorno
.env
.env.local
!.env.example

# Python
__pycache__/
.venv/
.pytest_cache/

# Node
node_modules/
.next/

Por qué .env queda excluido y .env.example no. El primero contiene las claves reales del entorno —contraseña de la base de datos, clave de firma de los tokens, clave de cifrado— y no debe salir del equipo. El segundo tiene las mismas variables con valores de ejemplo, y sirve para que cualquiera sepa qué configurar.

Se comprueba el estado y se registra la primera versión:

$ git status
$ git add .
$ git commit -m "Línea base del proyecto"
Captura 3 — Repositorio local inicializado Terminal mostrando git init, git status y la primera versión registrada con git commit

7. Paso 4 — Instalación del cliente de GitHub

Para crear y vincular el repositorio remoto desde la terminal se instala la herramienta oficial de GitHub: 

$ sudo apt install gh
$ gh --version
gh version 2.45.0
Captura 4 — GitHub CLI instalado Terminal mostrando la instalación y la salida de gh --version

8. Paso 5 — Autenticación con el servicio remoto

Se inicia la autenticación. El asistente pregunta el servicio (GitHub.com), el protocolo (HTTPS) y el método; al elegir el navegador, muestra un código de un solo uso que se introduce en la página que abre: 

$ gh auth login
? What account do you want to log into?  GitHub.com
? What is your preferred protocol for Git operations?  HTTPS
? Authenticate Git with your GitHub credentials?  Yes
? How would you like to authenticate GitHub CLI?  Login with a web browser

! First copy your one-time code: XXXX-XXXX
- Press Enter to open github.com in your browser...
✓ Authentication complete.

Se verifica que la sesión quedó establecida:

$ gh auth status
github.com
  ✓ Logged in to github.com account monjejuan448-ux (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'

El permiso repo es el que permite crear repositorios y enviar cambios; workflow, el que permite que el archivo de integración continua viaje con el código.

Captura 5 — Autenticación completada Terminal mostrando el proceso de gh auth login y la salida de gh auth status

9. Paso 6 — Creación del repositorio remoto y vinculación

Se crea el repositorio en GitHub y se vincula con el local en un solo comando:

$ gh repo create MONK-GRAIN-APP --public --source=. --remote=origin

Se comprueba que el remoto quedó asociado:

$ git remote -v
origin  https://github.com/monjejuan448-ux/MONK-GRAIN-APP.git (fetch)
origin  https://github.com/monjejuan448-ux/MONK-GRAIN-APP.git (push)

Y se envía el historial completo:

$ git push -u origin main
Captura 6 — Repositorio remoto creado y vinculado Terminal mostrando gh repo create, git remote -v y git push
Captura 7 — El repositorio en GitHub Navegador mostrando el repositorio publicado, con sus archivos y el historial de versiones visible

10. Equivalencias para otros sistemas operativos

Los pasos 2 a 6 son idénticos en cualquier sistema: lo único que cambia es cómo se instalan Git y el cliente de GitHub.

SistemaInstalación de GitInstalación de GitHub CLI
Linux (Debian, Ubuntu, Mint) sudo apt install git sudo apt install gh
Windows Instalador de Git for Windows desde git-scm.com winget install GitHub.cli
macOS brew install git brew install gh

12. Conclusión

El entorno de versionamiento queda instalado y configurado en sus dos ámbitos: Git 2.43 en el equipo, con la identidad del aprendiz y main como rama inicial, y GitHub como repositorio remoto vinculado mediante GitHub CLI 2.45 con autenticación por navegador.

El orden importa y por eso se documenta así: definir .gitignore antes de la primera versión evita que las claves del entorno entren en un historial del que después cuesta sacarlas.
