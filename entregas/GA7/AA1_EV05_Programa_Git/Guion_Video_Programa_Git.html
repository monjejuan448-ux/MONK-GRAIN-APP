1. Introducción

Esta evidencia se entrega como video MP4. El ejercicio ya está ejecutado y publicado; lo que este documento aporta es el guion para grabarlo: qué decir, qué comando ejecutar en cada momento y qué debe verse en pantalla.

El repositorio del ejercicio está en https://github.com/monjejuan448-ux/Programa-Git y su copia local, en la carpeta Programa-Git/ junto a este documento.

2. Objetivo

Demostrar en video que la herramienta de versionamiento quedó instalada y configurada, ejecutando los tres pasos que pide la guía: asociar un repositorio remoto público, enviar los cambios y verlos en GitHub, y registrar un archivo nuevo con el mensaje indicado.

Lo que debes hacer tú

Grabar el video. Duración estimada: 5 a 7 minutos. Empieza presentándote con tu nombre, como pide la guía, y explica cada requerimiento mientras lo ejecutas. Cualquier grabador sirve: OBS Studio, SimpleScreenRecorder o el grabador del sistema. Guarda el archivo como AA1_EV05_Video.mp4 en esta misma carpeta.

3. Preparación antes de grabar

  • Abre la terminal en la carpeta Programa-Git/.
  • Aumenta el tamaño de letra de la terminal: lo que no se lee en el video no cuenta como evidencia.
  • Ten abierto el navegador en https://github.com/monjejuan448-ux/Programa-Git.
  • Cierra lo que no vayas a mostrar.

Si quieres grabar el ejercicio desde cero. Los pasos ya están ejecutados, así que al repetirlos Git dirá que no hay nada que enviar. Para grabarlo en limpio, borra el archivo kotlin.txt y la última versión antes de empezar: 

$ git reset --hard HEAD~1
$ git push --force github main

Así el paso 3 vuelve a ser real durante la grabación.

4. Guion

Bloque 1 — Presentación (30 segundos)

A cámara o en voz sobre la pantalla:

«Buenas. Mi nombre es Eliana Chacon, del programa Análisis y Desarrollo de Software del SENA. En este video voy a demostrar la herramienta de versionamiento Git instalada y configurada, ejecutando los tres requerimientos de la evidencia AA1-EV05 sobre el repositorio Programa-Git.»

Muestra que el entorno está listo:

$ git --version
git version 2.43.0

$ git config --global --list
user.name=Eliana Chacon
user.email=juanmo1082@hotmail.com
init.defaultbranch=main

Bloque 2 — Primer requerimiento: asociar el remoto y listarlo (1 a 2 minutos)

«El primer requerimiento pide crear un repositorio público llamado Programa-Git, añadirlo al repositorio local y mostrar los remotos configurados.»

Muestra primero el repositorio ya creado en el navegador, y señala que es público. Luego, en la terminal:

$ git remote add github https://github.com/monjejuan448-ux/Programa-Git.git

$ git remote -v
github  https://github.com/monjejuan448-ux/Programa-Git.git (fetch)
github  https://github.com/monjejuan448-ux/Programa-Git.git (push)

Qué explicar mientras se ejecuta:

  • Que github es solo un nombre corto para no escribir la URL completa cada vez.
  • Que aparecen dos líneas porque Git distingue de dónde lee (fetch) y a dónde escribe (push), aunque aquí sea la misma dirección.

Bloque 3 — Segundo requerimiento: subir y ver el historial (1 a 2 minutos)

«El segundo requerimiento pide subir los cambios al remoto y mostrar el historial de versiones en GitHub.» 

$ git push github main

Aquí conviene explicar algo que la guía no dice y el instructor agradece: la guía usa master porque era el nombre antiguo de la rama principal; este repositorio usa main, que es el nombre por defecto actual de GitHub, y por eso el comando lleva main.

Pasa al navegador, recarga y muestra:

  • Los archivos ya publicados.
  • El historial de versiones (pestaña Commits), con su mensaje, autor y fecha.

Bloque 4 — Tercer requerimiento: kotlin.txt y «Añadido datos» (2 minutos)

«El tercer requerimiento pide crear un archivo kotlin.txt con mi nombre y correo, prepararlo, registrarlo con el mensaje "Añadido datos" y subirlo al remoto.» 

$ echo "Eliana Chacon" > kotlin.txt
$ echo "juanmo1082@hotmail.com" >> kotlin.txt
$ cat kotlin.txt
Eliana Chacon
juanmo1082@hotmail.com

$ git status
$ git add .
$ git commit -m "Añadido datos"
$ git push github main

Qué explicar:

  • Que git status muestra el archivo como no seguido antes de add, y preparado después: son las tres áreas de Git.
  • Que git commit registra la versión en el equipo, y que hasta git push ese trabajo no ha salido del disco.

Cierra mostrando el historial final:

$ git log --oneline
569eb02 Añadido datos
276bfa8 Repositorio del ejercicio de versionamiento

Y en el navegador, el archivo kotlin.txt ya publicado con su contenido.

Bloque 5 — Cierre (30 segundos)

«Con esto quedan demostrados los tres requerimientos: el repositorio remoto público asociado al local, el historial de versiones publicado en GitHub, y el archivo kotlin.txt registrado con el mensaje "Añadido datos". Gracias.»
